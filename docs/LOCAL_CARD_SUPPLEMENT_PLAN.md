# 로컬 이름·번호 보충 목록

사용자가 승인한 매니페스트/로컬 보충 목록 분리 방식을 구현합니다.

- 기존 IndexedDB `cardNames`, `cardNumbers`에는 서버 목록만 유지합니다. `cardListSupplement`에는 `{names: [], numbers: []}`를 저장합니다.
- 일반 이름·번호 검색, 메타데이터 조회, 개별 카드 크롤링, 팩 카드 크롤링의 성공 응답에서 실제 확인된 이름·번호를 추출합니다. 실패·대기 응답과 입력 문자열은 기록하지 않습니다.
- 매니페스트에 없는 항목을 보충 목록에 중복 없이 추가하고, 두 목록의 합집합으로 자동완성과 정규화 이름 목록을 즉시 갱신합니다. 시작 시 두 저장 영역을 복원합니다.
- 매니페스트 수신 시 이름·번호 각각 포함 여부를 비교합니다. 새 매니페스트 저장과 보충 목록 정리는 같은 IndexedDB 트랜잭션에서 처리하며, 여러 탭의 추가 항목은 저장 직전 최신 데이터를 읽어 병합합니다.
- 저장 실패 시 현재 세션의 보충 항목은 유지하고 서버 동기화 완료 시각은 앞당기지 않습니다. 상세 검색 캐시와 `cardNames.json`의 서버 형식은 유지합니다.

확인 항목: 신규 이름·번호 즉시 자동완성, 새로고침 복원, 오래된 매니페스트 수신 시 보충 항목 보존, 일부만 포함된 매니페스트 정리, 중복 응답, 팩의 다국어 결과, 실패·대기 응답 제외, 저장 실패 및 동시 탭 추가 보존. 자동 검증은 기존 사용자 승인 범위에서 필요한 회귀 검증만 수행합니다.

## 구현 및 확인 결과

- `public/script.js`의 `CardListCache`가 두 목록의 합집합을 자동완성에 전달합니다. `callApi`의 성공 응답에서 정보를 수집하고, `ClientCache.init`에서 영구 저장된 두 목록을 복원합니다.
- `MasterDB.updateCardLists`에서 최신 데이터를 읽어 병합하고, 매니페스트와 보충 목록을 같은 트랜잭션으로 저장합니다. 같은 탭의 저장은 순서대로 실행합니다. 서버의 이름 정규화 규칙과 동일하게 공백·유니코드를 처리하고 번호는 대문자로 비교합니다.
- 메타데이터에 포함된 실제 언어 슬롯에서 이름을 추출합니다. 상세 조회 응답의 대표 이름이 요청 문자열일 수 있으므로 언어 데이터가 있으면 대표 이름을 그대로 추가하지 않습니다.
- 격리 회귀 테스트 5개 통과: 즉시 반영·복원, 일부 항목 정리, 개별/팩 크롤링 및 오류 제외, 동시 추가 보존, 저장 실패 보존. JavaScript 구문 검사와 `git diff --check`도 통과했습니다.
- 실제 브라우저 IndexedDB와 화면 동작은 아래 순서로 확인합니다. 운영 데이터와 배포는 변경하지 않았습니다.

## 브라우저 확인 순서

1. 매니페스트에 없는 카드의 이름 또는 번호를 검색하여 성공 응답을 받습니다. 다른 입력 행의 자동완성에 해당 이름·번호가 나타나는지 확인합니다.
2. 개발자 도구에서 `YgoSynapseDB` → `masterCache` → `cardListSupplement`를 확인합니다. 서버 목록인 `cardNames`/`cardNumbers`에는 해당 항목이 추가되지 않아야 합니다.
3. 새로고침 후에도 보충 항목을 사용할 수 있는지 확인합니다.
4. 해당 항목이 없는 매니페스트를 동기화하면 보충 목록이 유지되어야 합니다. 포함된 새 매니페스트를 동기화하면 포함된 이름·번호만 보충 목록에서 사라지고 자동완성에는 계속 남아야 합니다.
5. 개별 및 팩 크롤링에서도 동일하게 확인합니다. 오류나 수집 대기 응답은 이름·번호를 추가하지 않아야 합니다.

상세 카드 정보·번호별 레어도·CID 캐시의 저장 정책은 이번 보충 목록 변경 범위에 포함하지 않습니다.
