# 함수 메모리 축소

사용자가 지정한 기준에 따라 현재 코드의 1GiB 설정을 512MiB로, 기존 512MiB 설정을 256MiB로 변경합니다. 기존 256MiB 및 미지정 함수는 유지합니다.

- 대상: 카드·팩 검색/크롤링, 자동 수집, 매니페스트 생성, 사용자/인벤토리, 덱, 번호 이관의 명시적 메모리 설정.
- 같은 구현을 참조하는 별칭도 변경된 설정을 사용합니다. 최초 대상은 별칭 포함 함수 25개(1GiB 17개, 기존 512MiB 8개)이며, 아래 이름 정리 후 남는 대상은 22개(기존 1GiB 14개, 기존 512MiB 8개)입니다.
- 타임아웃·CPU·동시 처리·최대 인스턴스 설정과 기능 로직은 변경하지 않습니다.
- 메모리 변경 단계에서는 코드만 수정했습니다. 후속 사용자 요청으로 커밋·푸시하며, `main` 푸시는 기존 GitHub Actions의 Firebase 배포를 시작합니다.

배포 후 확인: 개별 카드·팩 크롤링, 예약 수집, 전체 매니페스트 생성, 대형 인벤토리 조회/변경에서 메모리 초과 종료·응답 실패·지연 증가 여부를 확인합니다. Cloud Logging에서 메모리 초과/프로세스 종료/타임아웃 오류를 보고, 실제 메모리 사용 추이는 Cloud Monitoring 지표로 확인합니다. 문제가 있는 함수는 해당 설정만 이전 단계로 복원합니다.

현재 요청에서는 자동 테스트를 실행하지 않고 변경 설정을 코드로 검토합니다.

## 재생성 이름 정리 및 커밋

사용자 승인에 따라 HTTP 진입점과 내부 재생성 함수명을 `rebuildCardNames`로 통일합니다. 호출되지 않는 `rebuildAllCardIndexes`, `buildIndex`, `syncCardManifestToStorage` HTTP 별칭과 내부 `refreshCardManifest` 별칭을 제거합니다. 관련 테스트 정의와 운영 문서를 갱신하고 메모리 변경과 함께 커밋·푸시합니다. 작업 큐·잠금·대기 기록의 기존 이름과 다른 기능의 호환 별칭은 유지합니다. 운영에 남은 구형 함수 삭제는 배포 과정에서 별도로 확인합니다.
