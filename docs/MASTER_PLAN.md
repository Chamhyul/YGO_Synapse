# YGO시냅스 마스터 플랜

## 현재 변경 상태: 인벤토리 v2 / DB 직접 검색

2026-09-03 추가 승인에 따라 세 검색 인덱스 JSON 의존을 제거하고, `cardNames.json` 형식을 유지하며, 인벤토리 로드 시 CID를 자동 확보하는 v2 코드를 반영했습니다. 자동 실행 검증과 운영 배포는 하지 않았습니다.

현재 설계는 [INVENTORY_V2_PLAN.md](INVENTORY_V2_PLAN.md), 확인 절차는 [INVENTORY_V2_ROLLOUT.md](INVENTORY_V2_ROLLOUT.md)를 따릅니다. 아래 내용은 이전 네 파일 방식의 작업 이력이며, 파일 생성과 검색 부분은 새 문서가 대체합니다.

작성일: 2026-09-03. 이 세션에서 합의한 라우트–서비스 구조 및 변경 대기 목록 기반 갱신 계획을 기준으로 합니다.

## 순서와 상태

| 순서 | 작업 | 상태 |
|---|---|---|
| 1 | 기존 수정·저장·호출 경로 확인 | 완료. 착수 시 작업 트리 깨끗함 |
| 2 | 닉네임 및 주소 누락 복구 | 구현 완료, 격리 테스트 통과 |
| 3 | 버전·즉시 실행·연속 처리·잠금·복구 설계 | 수집 완료 시 첫 묶음 직접 실행으로 수정, 사용자 검증 대기 |
| 4 | 원본과 변경 대기 기록의 원자적 저장 | 수집 완료 후 직접 실행 연결 완료, 사용자 검증 대기 |
| 5 | 증분 갱신·실패 재처리 | 작업 큐 연속 처리로 수정 완료, 사용자 검증 대기 |
| 6 | 전체 재생성·기존 누락 복구 절차 | 도구 구현 완료, 운영 복구 대기 |
| 7 | 레거시 제거·명칭 통일 | 구현 완료. 전환용 호환 함수는 임시 유지 |
| 8 | 라우트–서비스 및 실행 진입점 정리 | 완료 |
| 9 | 통합 검증과 변경 검토 | 사용자 로컬 검증 대기. 기존 14개 테스트 및 SDK 통합 검증 통과, 이후 직접 실행 및 최초 파일 생성 수정은 미검증 |
| 10 | 배포·초기 복구·운영 확인 | 사용자가 GitHub를 통해 진행. 에이전트 배포 없음 |

## 구현 기준

- `cards`를 원본으로 유지하고 `pendingCardIndexUpdates/{cid}`에 UUID 버전과 서버 기록 시각을 함께 저장합니다.
- 단일 Firestore 배치에 원본과 대기 기록을 포함합니다. 번호 이관도 동일한 대기 기록 함수를 사용합니다.
- 단일 카드는 저장 직후, 팩은 해당 수집 묶음이 끝나는 즉시 실행 상태를 확인합니다. 실행 중인 작업이 없으면 첫 100개를 같은 호출 안에서 직접 처리하고 파일 저장까지 기다립니다.
- 실행 중인 작업이 있으면 변경 기록만 남깁니다. 예약만 되어 있고 아직 실행되지 않은 작업은 직접 실행으로 인계하고 이전 실행 ID를 무효화합니다.
- 작업당 최대 100개를 처리하고 남은 기록이 있으면 다음 Tasks 실행을 즉시 예약합니다. 대기열 확인과 종료/후속 예약 상태 전환은 같은 트랜잭션에서 수행합니다.
- `system/cardIndexDispatch`에 예약/실행 상태와 고유 실행 ID를 저장합니다. 동일 ID의 작업 제출은 중복 생성되지 않도록 합니다.
- 직접 실행 또는 후속 예약 실패는 호출자에게 오류를 전달하고 대기 기록을 보존합니다. 다음 수집 완료 시 다시 직접 실행할 수 있습니다. Tasks 작업 실패는 최대 5회 재시도합니다.
- 기존 `processCardIndexUpdates` 예약 함수는 5분마다 방치된 대기열의 실행만 복구합니다. JSON 갱신을 직접 실행하지 않습니다. 비정상 종료/재시도 소진 시 15분의 실행 유효 기간 만료 후 복구할 수 있습니다.
- 새 변경이 도착한 문서는 이전 작업이 삭제하지 않습니다. 모든 파일 저장 성공 후 버전을 대조해 삭제합니다.
- 일반 갱신·전체 재생성·목록 재생성은 `system/cardIndexWriter` 잠금을 공유합니다.
- 잠금 유효 시간은 15분이며 모든 배포 진입점의 최대 실행 시간은 540초 이하입니다. 비정상 종료 후 잠금 만료까지 작업이 지연될 수 있습니다.
- Storage 저장은 파일 버전이 일치할 때만 수행하고 충돌 시 실패합니다. 무조건 덮어쓰기 재시도를 하지 않습니다.
- 세 인덱스와 목록은 각각 저장되므로 네 파일을 동시에 전환하는 방식은 아닙니다. 부분 저장 실패 시 대기 기록을 유지하고 다음 처리에서 복구합니다.
- 전체 재생성과 증분 갱신은 `cardIndexBuilder`의 같은 생성 규칙을 사용합니다. 변경 카드의 이전 이름·번호 항목을 제거하고 현재 `info`로 다시 만듭니다.
- 인덱스 파일이 없으면 대기 중인 카드로 새 파일을 생성합니다. 준비 상태 ready는 실행 조건으로 사용하지 않습니다. 대기 기록이 없는 과거 카드의 누락이나 손상된 JSON은 전체 재생성으로 복구합니다.
- 전체 재생성은 원본을 문서 ID 순으로 500개씩 읽고 대기 기록을 삭제하지 않습니다. 스캔 중 발생한 변경은 이후 증분 작업이 반영합니다.
- 서버 인덱스 캐시는 1분입니다. 클라이언트는 검색 또는 탭 복귀 시 최대 1분에 한 번 공통 목록을 재확인합니다.

## 폴더와 책임

- `routes/`: HTTP 입력·인증·서비스 호출·응답
- `routes/admin/`: 관리자 HTTP 진입점
- `services/`: 카드 저장, 팩 처리, 인덱스 갱신, 수집 제어
- `schedules/`: 정기 자동 수집과 방치된 인덱스 대기열 실행 복구
- `tasks/`: 인덱스 연속 처리, 수집 이어하기, 번호 이관의 작업 큐 진입점
- `integrations/`: Sheets·Discord API 연동
- `scrapers/`: 카드·덱 HTML 수집·분석
- `utils/`: 공통 보조 및 저장소 접근

## 명칭과 호환

| 기존 | 새 이름 |
|---|---|
| 프론트엔드 getCardNameFromDb | searchCardByNo |
| 프론트엔드 getCardDetailsByName | searchCardByName |
| searchPackNew | searchPack |
| crawlPackBatchNew | crawlPackCardsBatch |
| getCardFullMetaByCid | getCardMetadata |
| 크롤러 crawlPack | crawlCardInPack |
| buildIndex | rebuildAllCardIndexes |

`keepAlivePing`, `checkMembership`, `cleanNumbersCollection`의 프론트엔드 주소를 제거했습니다. 마지막 함수는 주소 외 구현을 확인하지 못했으므로 실제 DB 삭제는 하지 않습니다.

배포 전환 중 기존 탭을 지원하기 위해 `searchPackNew`, `crawlPackBatchNew`, `getCardFullMetaByCid`, `buildIndex`를 새 구현의 임시 별칭으로 유지합니다. 기존 `buildIndex`도 같은 잠금과 관리자 POST 검사로 연결됩니다. 클라이언트 전환 확인 뒤 별칭과 배포 함수를 정리합니다.

## 검증 및 운영

검증 방법·제약과 배포·복구 순서는 `INDEX_ROLLOUT.md`에 기록합니다. 운영 검증을 마치기 전에는 전체 작업을 완료로 표시하지 않습니다.

## 사용자 검증·배포 방침

사용자가 로컬에서 직접 검증하고 GitHub를 통해 배포합니다. 에이전트는 추가 자동 검증·직접 배포·운영 복구를 실행하지 않습니다. 운영 배포 요청은 사용자 거절로 실행되지 않았습니다.

첫 전체 복구는 정상 수집의 선행 조건이 아닙니다. 새 파일은 대기 카드로 생성하며, 과거 카드 중 대기 기록이 없는 자료까지 복원할 때만 전체 재생성을 사용합니다.

## 이번 변경의 로컬 확인 항목

- 로컬 화면에서 새 카드가 포함된 팩을 수집하고, 완료 응답 시 Storage 인덱스 3개와 cardNames.json이 생성·갱신되었는지 확인합니다.
- 최초 직접 실행은 Tasks 없이도 수행합니다. 100개 초과분이나 처리 중 추가된 변경의 후속 실행에는 Tasks 에뮬레이터가 필요합니다.
- 실행 중 다른 수집을 완료하면 변경 기록을 기존 작업 또는 후속 작업이 처리하는지 확인합니다.
- 종료 직전 추가한 변경도 처리되고 최종 dispatch 상태가 idle인지 확인합니다.
- 파일 저장 실패 시 성공으로 표시하지 않고, 대기 기록이 유지되는지 확인합니다.
- 이번 변경 후 자동 테스트·에뮬레이터 실행·배포는 에이전트가 하지 않았습니다.

## 카드 텍스트 줄바꿈 보정

- 수집 시 실제 HTML br 태그와 텍스트로 들어온 `<br>`, `<br/>`, `<br />`를 개행으로 통일합니다. 일반 효과와 펜듈럼 효과에 동일하게 적용합니다.
- 이미 저장된 텍스트도 상세 화면에서 같은 줄바꿈 보정을 거칩니다. 다른 HTML을 해석하지 않고 textContent로 표시합니다. DB 일괄 변경은 하지 않습니다.
- 사용자 확인: 제시한 젬나이트 카드에서 소재와 효과가 두 줄로 구분되는지, 펜듈럼 효과의 줄바꿈도 유지되는지 확인합니다. 새로 수집한 원본에는 br 문자열 대신 개행이 저장되는지 확인합니다. 자동 검증은 실행하지 않습니다.

## 백엔드 검토 피드백 반영

1. 레어도 저장 보호: 파일 버전 조건으로 저장하고 충돌 시 최신 파일을 다시 읽어 병합합니다. 최초 시도 후 최대 3회 재시도합니다. 파일 부재 외 읽기 오류와 JSON 형식 오류는 저장을 중단하며 저장 성공 후 캐시를 갱신합니다. 구현 완료, 사용자 검증 대기.
2. info 설명: cardScraper.js와 cardService.js 상단에 위치별 의미와 특수값 주석을 추가했습니다. 저장 형식과 인덱스는 유지합니다.
3. 미사용 import: integration.js의 google과 Google 시크릿 3개 가져오기 선언을 제거했습니다. Sheets 연동과 시크릿 정의는 유지합니다.
4. 사용자 검증: INDEX_ROLLOUT.md에 확인 항목을 추가합니다. 자동 테스트와 배포는 실행하지 않습니다.

검색 보충 크롤링, 캐시 정책, Node.js, 멤버십, 메모리 진단은 이번 수정에서 제외합니다. 카드 원본 저장 후 레어도만 실패하면 기존 동작대로 원본을 유지하고 레어도 실패를 구분해 로그에 기록합니다.
